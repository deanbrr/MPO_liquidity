**Reviewer:** adversarial design critic, buildability lens · **Date:** 2026-10-18 · **Documents:** `design/ARCHITECTURE.md` v1.0 (ARCH, 17:30) and `design/BUILD_SPEC.md` v1.0 (BS, 19:15), both read in full · **Also read:** `design/00_DESIGN_BRIEF.md` (brief, incl. §7–§9 and R16), the research files cited below, the judge reports and `design/addenda/chat_*.md`.
**Method.** I traced every cross-module signature in BS §3–§5 against its producers and consumers, the import table (BS §4.0) and the wave plan (BS §9), and compared ARCH with BS. I ran environment and numerical checks with `C:\users\dean\ai_envs\adic_tpa_lab\.venv\Scripts\python.exe`: installed packages, the highspy/CLARABEL/anthropic API surface, Pydantic behaviour, sampler and RNG speed, and the arithmetic behind budgets and acceptance values. Timings marked [M] are measurements of library functions on this laptop (Intel Core Ultra 9 285HX, 24 cores, ≈95 GB RAM, the spec's reference machine), not ADIC data.

## Verdict

BUILD_SPEC is unusually complete. Units, signs, axis order, seeds, error codes, file ownership and named tests are fixed. The environment matches it: every pinned package is installed, every HiGHS option and CLARABEL setting named in BS §5.7 exists, the installed anthropic 1.15.0 `beta.messages.parse` accepts `output_format`, `betas` and `fallbacks`, and the sealed PE-history fixture hash matches. Most of the arithmetic holds (H size, node counts, ε′ conversions, CP gate example, allocation totals).

**It is not yet buildable as written, and the contracts should not be frozen at the end of Wave 0 in their current form.**

- **Wrong numbers.** One defect would produce wrong numbers on the binding safety metric. Recourse sales decided in the ledger never reach the engines that own the units, so sold assets keep paying distributions (BUILD-01).
- **Missing data.** One MVP deliverable depends on data that is not on disk. The B1 search family needs about 20 monthly factor histories; the only panel on disk has 23 columns, most of them other series (BUILD-02).
- **Day-one failure.** The global Pydantic rule `strict=True` together with `load_yaml` fails on every config file. I confirmed this with the installed pydantic 2.14 (BUILD-03).
- **Performance targets.** The per-component budgets add to more than twice B1. B2 and B12 are also infeasible on the spec's own caps (BUILD-05–07, BUILD-19).
- **Interfaces.** About a dozen interfaces lack the arguments, producers or types they need: beliefs to engines, misspecification overrides, the `select`/`price`/`phase2` signatures, context types, `LeverSet`, the CFA tuning loop, simulated observables, and a stress-filter input the cube does not carry (BUILD-04, -11–16, -22–24).
- **Requirements and principles.** R16 (chat with the model) and brief §9 (since-inception IRR/MOIC marks with cases and an existing archive) are not carried into contracts, WPs or tests. LLM output schemas ask the model for engine-owned numbers and the human `confirmed` flag, in conflict with P1 (BUILD-08–10).
- **Over-scoped first build.** Increment 1 is wider than ARCH §11.6 without an ADR, and it is gated on validation jobs that cannot run in it (BUILD-17, BUILD-18).

**Recommendation:**

1. Add a contract-hardening revision and a Wave-0 "walking skeleton" gate before tagging `contracts-v1.0`: every Protocol and cross-WP call exercised once on `mini_book` with fakes.
2. Make an explicit data decision for B1/B2.
3. Re-baseline the performance table so its lines sum to the targets, with profile tests.
4. Add the R16 and brief-§9 S-ADRs.

Once those land, the end-to-end demo is reachable on this machine.
