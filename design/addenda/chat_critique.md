# Critique: CHAT_ANALYST.md (R16, the conversational analyst)

**Reviewer:** adversarial design critic, R16 lens · **Date:** 2026-10-18 · **Document:** `design/addenda/CHAT_ANALYST.md` v1.0 (CA), all 599 lines read · **Checked against:** brief §1 (R16), §2 (P1, P7, P8, P12, P13), §9; `ARCHITECTURE.md` v1.1 (ARCH: §1, §2.1, §2.4 TB1–TB9, §3.3, §7.2–7.3, §7.5, §7.10, §7.13, §8.1, §8.4, §8.6–8.12, §9.3–9.7, §10.6–10.7, §11.1–11.7, ADR-44, ADR-46, ADR-47); `BUILD_SPEC.md` v1.1 as on disk (BS: §0.3 S-ADR-01–44, §3.16, `contracts/analyst.py`, §4.28–4.34, §7.1–7.13, §8.1–8.8, §9, §10.2); the bundled claude-api Python `README.md` and `tool-use.md`, plus `shared/tool-use-concepts.md` and the Opus 5.5 section of `shared/model-migration.md`; `chat_golden_questions.json` (GQ, 140 items); `chat_inventory.md` (CI) §3.8, §4–5; `chat_questions.md` (CQ) §5, §10; `chat_research.md` (CR) §3.
**Method.** I traced every CA rule to the mechanism that enforces it, looking for paths where a number, a label or a what-if reaches a user without that mechanism. I compared CA with ARCH v1.1 (whose §8.12 says the addendum "may refine names and schemas, not these rules") and with BS v1.1. I mapped all 140 golden items through CA's tools and checked the installed `anthropic` 1.15.0 and `mcp` 2.3.0 source wherever CA depends on SDK behaviour. "Checks run" at the end lists what was executed.

> **SYNTHETIC – NOT ADIC DATA.** No ADIC values appear here. Golden-item ids and thresholds are quoted from the design documents.

## Verdict

CA is careful and mostly well grounded. It has one deterministic service with thin surfaces, typed tools, rendered placeholders, server-side entitlements, back-translations generated from templates, confirmation by a human on ADIC surfaces, and no write tool. It also removes a real BS defect: BS §7.11 lets the analyst MCP server call `optimize_h` directly, with no confirmation. The SDK and MCP calls it names exist in the installed packages.

**It is not ready to merge.** Three of its five critical issues come from the Claude Code / Desktop surface:

- **The MCP surface breaks P1, R16 and TB9 in three ways.**
  - The client's native file, shell and web tools bypass every analyst control. In DEV/SYNTHETIC mode they can read the sealed truth and the seal salt (CHAT-01).
  - A what-if can run on a confirmation that an agent client produces automatically (CHAT-02).
  - The client's unvalidated prose is opened to every persona (CHAT-03).
- **Provenance is not meaning.** Placeholders prove where a number came from, not that it is the quantity the sentence claims. Handles that are reused across turns make citing the wrong fact likely (CHAT-04). One LLM-written float is rendered as the user's input (CHAT-05).
- **What-ifs.** Confirmation binds single overrides, but the model chooses the combination that runs (CHAT-06). The loop in §3.3 runs truncated tool calls (CHAT-07). The Replay plan cannot work with the chosen loop (CHAT-08).
- **Golden set.** About 13 items cannot pass as specified. They need ranked or filtered holding lists, goal-seek or reverse-stress drafts, or certified probabilities after a lever change (CHAT-09 to CHAT-11).
- **Fit with the other documents.**
  - CA collides with BS v1.1's S-ADR and WP numbers and with its `contracts/analyst.py` (CHAT-17).
  - It widens increment 1 well beyond ARCH's "thin slice" (CHAT-18).
  - It copies KL thresholds that ARCH v1.1 has corrected (CHAT-19).

**Counts:** 5 critical, 15 high, 17 medium, 3 low.

**Recommendation, in order:**

1. **MCP surface.** For increment 1, make it read-only, for the TPA/operator persona only, on SYNTHETIC data.
   - Launch the client from an empty working directory, with managed settings that deny its native tools.
   - Give MCP no `run_whatif`.
   - Store confirmations in the registry, signed per person (CHAT-01, -02, -03, -14).
2. **Semantic binding.**
   - Make handles unique per session and render each fact's label next to its value.
   - Add `CLAIM_FACT_MISMATCH` and `UNBOUND_COMPARATIVE`.
   - Parse user numbers in code instead of taking them from the model (CHAT-04, -05, -13).
3. **What-if path.**
   - Confirm one what-if bundle as a whole.
   - Run tools only when `stop_reason == "tool_use"`.
   - Pick a single agent loop and Replay mechanism (CHAT-06, -07, -08).
4. **Tools.** Add `list_holdings`, goal-seek and reverse-stress drafts, and a table that maps each requested output to its minimum tier (CHAT-09 to -11).
5. **Alignment.**
   - Re-base CA on BS v1.1's numbering and contracts.
   - Cut increment 1 back to ARCH §11.6.
   - Adopt ARCH v1.1's KL thresholds (CHAT-17 to -19).

## What holds (do not re-open)

- One `AnalystService` serves thin surfaces, with entitlements on the server, no write or outbound tool, `Registry(readonly=True)` and an exploration-plane evaluator. Removing BS §7.11's direct `optimize_h` and taking `register_forecast` off every LLM-facing surface are both correct.
- Back-translations are generated from templates. The effective view after shrinkage is shown, and no outcome number appears before confirmation (O2). Promotion into a `DecisionRecord` needs an exact Python recompute and keeps the evidence plane "exploratory".
- The brief §9 data facts are carried through: since-inception net IRR and MOIC marks; cases read as P10/P50/P90; bitemporal `as_of` and `recorded_at`; since-inception IRR greyed as sunk; credibility hidden below n_eff = 20, one group per answer, information value in dollars.
- The politics rules are carried as codes: `LEAGUE_TABLE`, `GRADE_LANGUAGE`, `NAMED_PERSON_REGRET`, `MULTI_GROUP_CREDIBILITY`. The model never sees the user's identity.
- The Ask HTTP hardening is sound: loopback bind, one-time code exchanged for an HttpOnly cookie, Host, Origin and CSRF checks, no CORS headers, CSP, 64 kB request cap.
- The SDK and MCP calls named exist in the installed versions, with the parameters CA uses (see "Checks run").
  - `client.beta.messages.tool_runner` accepts `max_iterations`, `fallbacks`, `betas`, `output_config`, `system` and `thinking`, and the installed runner resumes `pause_turn`.
  - `@beta_tool` accepts `strict` and `input_schema`; `mcp_tool` accepts `strict`.
  - `MCPServer(name, instructions, version)` exists, as does `.tool(annotations=, meta=, structured_output=)`; `ToolAnnotations` uses snake_case fields; `Context.elicit` and `Context.report_progress` exist.
  - The request settings follow the docs: thinking adaptive with an explicit effort, no sampling parameters, no prefill, `tool_choice` left on auto, a refusal check and `_request_id` logging. The beta header `-2026-07-01` is correctly paired with `fallbacks="default"`.
